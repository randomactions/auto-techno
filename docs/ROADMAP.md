# Roadmap

Auto Techno now has one current runtime and one executable product. Work should
strengthen that path rather than add alternative engines or comparison modes.

## Current baseline

- one-button autonomous macOS app;
- fixed 130 BPM and one private, reproducible canonical identity;
- phrase candidates selected with temporal memory, interest scoring, ensemble
  arbitration, and dramatic-debt repair;
- resolved performance bars make arbitrated events authoritative for audio and
  telemetry, with sixteen-bar punctuation over adaptive phrase lengths;
- a three-step driver advancing a five-stage upper-voice follower, plus bounded
  sixteen-bar chapters and regular identity returns;
- required Scene DNA and synth plans;
- stable modal/timbral identity, restrained contrast-only topology mutation,
  and a protected kick/companion foundation;
- exact private role stems, a bounded preparation-time kick/foundation fader,
  and a truthful fixed-decibel waveform display;
- detached preparation, sample-time scheduling, and route recovery;
- objective preflight for finite samples, peaks, DC, low-end correlation,
  boundaries, masking, and continuation.

## Next validation work

Local implementation gates currently pass: the complete 34-test suite, optimized
release build, and one-button READY/LIVE/PAUSED/resume smoke all succeeded with
Xcode 26.6 / Apple Swift 6.3.3. Repeat them on the exact release head.

1. Smoke-test late-successor repetition and real 44.1/48 kHz route recovery.
2. Compare the canonical baseline and candidate at matched loudness at the first
   macro, first chapter change, contrast, break, release, and identity return.
3. Complete the 60-minute physical-output soak with pause/resume, route changes,
   interruption, and sleep/wake before a release-ready claim.

## Product development

Musical improvements must begin with one concrete listening observation. Add the
smallest reproducible rule that addresses it, compare the same canonical journey
at matched loudness, and keep it only when the intended perceptual result is
confirmed. Prefer meaningful performance structure and synth authorship over
marginal DSP controls. Keep all new control surfaces semantic and
listener-facing.

The first automatic-balance slice is intentionally limited to kick versus the
protected foundation. Consider percussion or upper-role gain adaptation only
after this slice passes matched-loudness listening; do not turn stem measurement
into a general-purpose mixer or expose it in the product.

## Non-goals

- restoring retired reference executables or 32/96-bar comparison paths;
- exposing internal Core or DSP libraries as supported products;
- adding configurable treatment, mastering, effect, stem, rhythm, synth-engine,
  or performance-model switches;
- moving planning or mutable preparation work onto the real-time callback;
- accepting sample changes from objective metrics alone.
