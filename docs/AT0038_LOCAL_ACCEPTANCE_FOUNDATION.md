# AT-0038 local acceptance foundation

This foundation checks the existing descriptive local-feature projections. It
cannot admit `verified-no-change`; `roadmap_integrity.py` retains its unconditional
missing-authority refusal. It adds no renderer, evaluator, profile, quality
threshold, correction, or runtime state. All work stays in the detached test
harness, before diagnostic serialization.

The canonical owners remain `ProfessionalEvidenceReportBank` and the existing
DSP local-evidence types. `AT0038LocalEvidenceAcceptanceSupport` is test-owned:
it reconstructs per-bar kick/foundation active-RMS ratios and every masking
bar/role-pair/band observation from the original complete typed candidate. It
compares schema, evidence version, engine, policy, report and plan fingerprints,
checkpoint, rate, bar geometry, availability, counts and all projected values.
A native bank must cover each canonical checkpoint at each required rate exactly
once. The existing opt-in diagnostic journey invokes this check on fresh typed
reports; saved trajectory JSON cannot enter the helper.

The existing `professionalEvidenceReportBank` test also exercises a complete
native-rate synthetic typed bank with all fourteen checkpoint/rate identities,
repeated reconstruction, and exact equality with both original projections. A
valid complete one-rate 8 kHz bank must refuse native coverage. These are bounded
constructor fixtures, not full native journeys or a calibration cohort. Their
existing test and evidence ownership remain unchanged; no new state, module,
flow owner or runtime boundary requires a map-manifest change in this follow-up.

The six criteria below come from the private AT-0038 plan's “Tests and automated
quality evidence” section. Historical v29 completion prose and its observed
36-seed/504-report cohort and 15-seed/210-report rerenders describe historical
support. They cannot provide current engine, source, profile or plan authority.

| Plan criterion | Bounded foundation | Evidence still required for positive admission |
| --- | --- | --- |
| Equal acceptable mean, independently reconstructed local defect | Existing equal-mean/local-spread and masking fixtures; new original-candidate field reconstruction | Current fixture results bound to exact implementation, producer and plan |
| Safe/neutral and absent/inapplicable availability | Existing local-evidence availability and malformed-source controls preserved | Current results for every applicable case; absence cannot become numeric zero |
| Complete source, local geometry, native rates/checkpoints, determinism | Typed native-bank completeness check; exact field checks; repeated focused reconstruction and altered-source/bar/role/band controls | Complete current fixed calibration cohort, unique bank/report membership, no omissions/duplicates, paired-count histograms, all applicable extrema rerenders with exact source/local equality |
| Local failure remains non-compensable | Altered local fields refuse while aggregate identity/counts stay fixed; existing independent-dimension verdict controls preserved | Current item-specific proof that favorable peers or aggregates cannot hide each applicable local deficit; descriptive spread alone is no failed quality verdict |
| No unsupported threshold, confidence, activation or promotion | Production sources/resources and gate vocabulary unchanged | Exact source/resource continuity and applicable qualification evidence; historical profile bounds cannot stand in for current authority |
| Focused Release plus integrity/citations/contracts/map/diff | Focused and repository validation required for this feature branch | Complete current implementation, focused-local, full-local and automated-quality gates, and every other applicable existing objective gate |

A later item-specific controller verifier must bind the exact item outcome,
ordered dependencies, private plan bytes, clean immutable source, producer
identity and semantic report coverage. An unknown item, stale source or plan,
partial matrix, missing applicability, generic passed label or diagnostic archive
must refuse. This layer does not register such a verifier or manufacture a
positive receipt. Full native studies remain owned by the qualification chat;
this change is reviewed and validated with focused controls in an isolated build.
