# Evolve Autonomous Sound

1. Read `docs/PRODUCT.md`, `docs/SOUND_QUALITY.md`, and
   `docs/AUTONOMOUS_RUNTIME_PROVENANCE.md`.
2. Start from an automatically detected deficit or an optional concrete human or
   source observation. Name the canonical checkpoint and falsifiable evidence;
   avoid adjectives without an observable engine consequence.
3. Locate the deficit before changing PCM: distinguish the resolved score, dry
   voice, role bus, generated graph, controller, and final output path. Identify
   the existing canonical owner, shared state, continuation, and fallback. Do not
   add another engine, renderer, profile, or user-facing switch.
4. Preserve the exact engine and quality-policy baseline plus the private
   canonical journey regions that expose the deficit.
5. Implement one reusable vertical slice: musical planning and future selection
   in `AutoTechnoCore`; signal-local rendering, measurement, and bounded
   correction in `AutoTechnoDSP`; transport/presentation only in
   `AutoTechnoApp`. Summarize DSP evidence before it crosses into future Core
   decisions; do not make Core depend on DSP types.
6. Trace every new parameter through resolved score or renderer, intended PCM,
   truthful evidence, and bounded influence on an unscheduled future decision.
   Connect or remove disconnected state before expanding it.
7. Add deterministic structural/DSP tests and a machine-readable offline quality
   comparison. Keep candidate count, corrective passes, state, slew, hysteresis,
   timing, and fallback bounded.
8. Promote only when required automated hard gates and multidimensional quality
   checks pass. If the required harness, schema, or policy version does not exist
   yet, mark qualification unavailable and implement the missing foundation
   without claiming promotion. Human listening may open another deficit; it
   never overrides the automated result.
9. Keep reference audio and generated WAVs local and untracked. Commit only
   non-reconstructable derived profiles and reproducible reason-coded evidence.

Follow `docs/VIDEO_ANALYSIS_PROTOCOL.md` for video-derived hypotheses. Read
[references/quality-loop.md](references/quality-loop.md) when changing candidate
evaluation, quality state, controllers, live feedback, reference calibration, or
promotion rules. Use `protect-realtime-audio` whenever the render, scheduling,
buffer, or callback-feedback path changes.
